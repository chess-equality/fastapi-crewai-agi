# FastAPI + CrewAI Template

This is the [FastAPI full-stack template](https://github.com/fastapi/full-stack-fastapi-template)
with **CrewAI** integrated into the backend. It gives you a React + FastAPI + PostgreSQL
stack where AI agent crews and flows can be triggered through the FastAPI API.

## How to Run

### Requirements

- [Docker](https://www.docker.com/) and Docker Compose
- [uv](https://docs.astral.sh/uv/) (for running the backend locally)
- [Bun](https://bun.sh/) (for running the frontend locally)

### 1. Configure the environment

The project uses environment-specific `.env` files. The default environment is `local`.

Copy the reference file and edit `.env.local` with your real keys and generated secrets:

```bash
cp .env.example .env.local
```

Set at least the following:

```dotenv
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini
```

Generate strong random values for the security and database credentials:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Update `SECRET_KEY`, `POSTGRES_PASSWORD`, and `FIRST_SUPERUSER_PASSWORD` in `.env.local` with values generated by that command.

To use a different environment, set `ENVIRONMENT` before running any command, e.g. `ENVIRONMENT=staging ./scripts/compose.sh up -d`.

### 2. Run the full stack with Docker Compose

The easiest way to run everything is with Docker Compose:

```bash
docker compose watch
```

The first launch may take a minute while the database starts and the pre-start script creates the initial tables and superuser.

Once ready, open:

- Application: <http://localhost:8000>
- API docs (Swagger UI): <http://localhost:8000/docs>
- ReDoc: <http://localhost:8000/redoc>
- Adminer (DB UI): <http://localhost:8080>
- Traefik dashboard: <http://localhost:8090>
- Mailcatcher: <http://localhost:1080>

To see logs:

```bash
./scripts/compose.sh logs
```

To stop:

```bash
./scripts/compose.sh down
```

### 3. Run the backend locally

If you prefer to run the backend outside of Docker for faster iteration, start only the supporting services:

```bash
./scripts/compose.sh up db mailcatcher -d
```

Then, from the `backend` directory, sync dependencies and start the development server:

```bash
cd backend
uv sync
uv run fastapi dev app/main.py
```

The API will be available at <http://localhost:8000>.

### 4. Run the frontend locally

For frontend hot-reload, from the `frontend` directory:

```bash
cd frontend
bun install
bun run dev
```

Then open <http://localhost:5173>.

When the stack is running through Docker Compose, the built frontend is served by FastAPI at <http://localhost:8000>. The Vite dev server is only needed when you want to work on the frontend outside the Docker build.

## CrewAI Quick Start

### Add your LLM key

Copy `.env.example` to `.env.local` and fill in at least one provider key:

```dotenv
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini
```

### Run the backend

```bash
cd backend
uv run fastapi dev app/main.py
```

### Trigger a flow

The demo flow lives under `backend/app/crews/demo_flow`. Call it with:

```bash
curl -X POST http://localhost:8000/api/v1/crews/demo_flow/kickoff \
  -H "Content-Type: application/json" \
  -d '{"inputs": {"topic": "AI Agents"}}'
```

### Add a new flow

1. Generate a new flow:

   ```bash
   uv run crewai create flow my_flow --skip_provider
   ```

2. Move the generated package into `backend/app/crews/`:

   ```bash
   cp -r my_flow/src/my_flow backend/app/crews/my_flow
   ```

3. Update `backend/app/crews/my_flow/main.py` so the `kickoff` helper accepts an optional `inputs` dict:

   ```python
   def kickoff(inputs: dict | None = None):
       ...
   ```

4. Restart the backend. The new flow is automatically exposed at:

   ```
   POST /api/v1/crews/my_flow/kickoff
   ```

The `crews` router in `backend/app/api/routes/crews.py` discovers any flow package under `backend/app/crews/` that contains a `main.py` with a `kickoff` callable.

### Notes

- Python is pinned to **3.12** because CrewAI requires `<3.14`.
- The workspace virtual environment is at the project root (`.venv`). `backend/.venv` is a symlink to it so the IDE interpreter path stays valid.

## Technology Stack and Features

- ⚡ [**FastAPI**](https://fastapi.tiangolo.com) for the Python backend API.
  - 🧰 [SQLModel](https://sqlmodel.tiangolo.com) for the Python SQL database interactions (ORM).
  - 🔍 [Pydantic](https://docs.pydantic.dev), used by FastAPI, for the data validation and settings management.
  - 💾 [PostgreSQL](https://www.postgresql.org) as the SQL database.
- 🚀 [React](https://react.dev) for the frontend.
  - 🧩 Built into the backend image and served by FastAPI on the same domain as the API.
  - 💃 Using TypeScript, hooks, [Vite](https://vitejs.dev), and other parts of a modern frontend stack.
  - 🎨 [Tailwind CSS](https://tailwindcss.com) and [shadcn/ui](https://ui.shadcn.com) for the frontend components.
  - 🤖 An automatically generated frontend client.
  - 🧪 [Playwright](https://playwright.dev) for End-to-End testing.
  - 🦇 Dark mode support.
- 🐋 [Docker Compose](https://www.docker.com) for development and production.
- 🔒 Secure password hashing by default.
- 🔑 JWT (JSON Web Token) authentication.
- 📫 Email based password recovery.
- 📬 [Mailcatcher](https://mailcatcher.me) for local email testing during development.
- ✅ Tests with [Pytest](https://pytest.org).
- 📞 [Traefik](https://traefik.io) as a reverse proxy / load balancer.
- 🚢 Deployment instructions using Docker Compose, including how to set up Traefik to handle automatic HTTPS certificates.
- 🏭 CI (continuous integration) and CD (continuous deployment) based on GitHub Actions.

## How To Use It

You can **just fork or clone** this repository and use it as is.

✨ It just works. ✨

### How to Use a Private Repository

If you want to have a private repository, GitHub won't allow you to simply fork it as it doesn't allow changing the visibility of forks.

But you can do the following:

- Create a new GitHub repo, for example `my-full-stack`.
- Clone this repository manually, set the name with the name of the project you want to use, for example `my-full-stack`:

```bash
git clone git@github.com:fastapi/full-stack-fastapi-template.git my-full-stack
```

- Enter into the new directory:

```bash
cd my-full-stack
```

- Set the new origin to your new repository, copy it from the GitHub interface, for example:

```bash
git remote set-url origin git@github.com:octocat/my-full-stack.git
```

- Add this repo as another "remote" to allow you to get updates later:

```bash
git remote add upstream git@github.com:fastapi/full-stack-fastapi-template.git
```

- Push the code to your new repository:

```bash
git push -u origin master
```

### Update From the Original Template

After cloning the repository, and after doing changes, you might want to get the latest changes from this original template.

- Make sure you added the original repository as a remote, you can check it with:

```bash
git remote -v

origin    git@github.com:octocat/my-full-stack.git (fetch)
origin    git@github.com:octocat/my-full-stack.git (push)
upstream    git@github.com:fastapi/full-stack-fastapi-template.git (fetch)
upstream    git@github.com:fastapi/full-stack-fastapi-template.git (push)
```

- Pull the latest changes without merging:

```bash
git pull --no-commit upstream master
```

This will download the latest changes from this template without committing them, that way you can check everything is right before committing.

- If there are conflicts, solve them in your editor.

- Once you are done, commit the changes:

```bash
git merge --continue
```

### Configure

You can then update configs in the `.env` files to customize your configurations.

Before deploying it, make sure you change at least the values for:

- `SECRET_KEY`
- `FIRST_SUPERUSER_PASSWORD`
- `POSTGRES_PASSWORD`

You can (and should) pass these as environment variables from secrets.

Read the [deployment.md](./deployment.md) docs for more details.

### Generate Secret Keys

Some environment variables in the `.env` file have a default value of `changethis`.

You have to change them with a secret key, to generate secret keys you can run the following command:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Copy the content and use that as password / secret key. And run that again to generate another secure key.

## How To Use It - Alternative With Copier

This repository also supports generating a new project using [Copier](https://copier.readthedocs.io).

It will copy all the files, ask you configuration questions, and update the `.env` files with your answers.

### Install Copier

You can install Copier with:

```bash
pip install copier
```

Or better, if you have [`pipx`](https://pipx.pypa.io/), you can run it with:

```bash
pipx install copier
```

**Note**: If you have `pipx`, installing copier is optional, you could run it directly.

### Generate a Project With Copier

Decide a name for your new project's directory, you will use it below. For example, `my-awesome-project`.

Go to the directory that will be the parent of your project, and run the command with your project's name:

```bash
copier copy https://github.com/fastapi/full-stack-fastapi-template my-awesome-project --trust
```

If you have `pipx` and you didn't install `copier`, you can run it directly:

```bash
pipx run copier copy https://github.com/fastapi/full-stack-fastapi-template my-awesome-project --trust
```

**Note** the `--trust` option is necessary to be able to execute a [post-creation script](https://github.com/fastapi/full-stack-fastapi-template/blob/master/.copier/update_dotenv.py) that updates your `.env` files.

### Input Variables

Copier will ask you for some data, you might want to have at hand before generating the project.

But don't worry, you can just update any of that in the `.env` files afterwards.

The input variables, with their default values (some auto generated) are:

- `project_name`: (default: `"FastAPI Project"`) The name of the project, shown to API users (in .env.local).
- `stack_name`: (default: `"fastapi-project"`) The name of the stack used for Docker Compose labels and project name (no spaces, no periods) (in .env.local).
- `secret_key`: (default: `"changethis"`) The secret key for the project, used for security, stored in .env.local, you can generate one with the method above.
- `first_superuser`: (default: `"admin@example.com"`) The email of the first superuser (in .env.local).
- `first_superuser_password`: (default: `"changethis"`) The password of the first superuser (in .env.local).
- `smtp_host`: (default: "") The SMTP server host to send emails, you can set it later in .env.local.
- `smtp_user`: (default: "") The SMTP server user to send emails, you can set it later in .env.local.
- `smtp_password`: (default: "") The SMTP server password to send emails, you can set it later in .env.local.
- `emails_from_email`: (default: `"info@example.com"`) The email account to send emails from, you can set it later in .env.local.
- `postgres_password`: (default: `"changethis"`) The password for the PostgreSQL database, stored in .env.local, you can generate one with the method above.
- `sentry_dsn`: (default: "") The DSN for Sentry, if you are using it, you can set it later in .env.local.
